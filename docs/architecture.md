# 架构说明

## 窗口

- `orb-window`：悬浮球、第一层五个分类花瓣和提醒轻卡片。
- `panel-window`：五类功能面板、设置和二级弹窗；默认隐藏。
- 两个窗口加载同一个前端入口，根据 Tauri 窗口标签挂载不同根组件。

## 边界

- Vue 负责 UI、状态、动画、转换逻辑和输入校验。
- `src/services/tauri` 是所有前端系统调用的唯一入口。
- Rust command 只负责窗口、文件、剪贴板、托盘、快捷键和受控进程启动等系统能力。
- 设置与 SQLite 将分别通过 repository 封装，组件不会直接访问存储插件。

## 窗口通信

- 需要返回值的操作使用 Tauri command，例如打开、关闭或切换窗口。
- 小型状态通知使用定向事件，例如面板分类变化。
- 剪贴板图片等大数据不通过事件传递，使用文件或 command/channel。

## 数据与设置

- 主题、运行模式、快捷键、悬浮球外观、提醒配置、收藏和常用入口通过 repository 封装后写入 Tauri Store。
- 提醒记录、剪贴板历史、临时中转元数据与最近使用通过 repository 访问 SQLite。
- 剪贴板图片缓存和临时中转副本只写入应用私有目录；清理命令不会接收任意用户目录作为删除目标。
- “清除数据并重置设置”先清除业务数据，再恢复默认快捷键、工作模式和各模块设置，并关闭开机启动。

## 系统设置与模式

- `app/stores/settings.ts` 是工作、静默、完全暂停三种模式的前端事实来源。
- `orb-window` 将模式映射到健康提醒和剪贴板监听；托盘通过定向事件请求切换，再由设置 store 持久化。
- 全局快捷键采用“先注册新组合、成功后释放旧组合”，避免设置失败时丢失原快捷键。
- 开机启动、全局快捷键、托盘勾选和退出均通过 `src/services/tauri/settings.ts` 进入受控插件或 Rust command。

## 悬浮球窗口

- 前端 Pinia store 维护单一 `OrbUiState` 状态机，非法跨级转换会被拒绝。
- Rust 根据悬浮球所在显示器的物理工作区计算展开窗口、面板位置和四边吸附目标。
- 花瓣位置由 TypeScript 纯函数计算，便于覆盖左右、上下和角落边界测试。
- 展开窗口通过全局光标位置轮询判断是否位于主球/花瓣热区；透明区域临时启用 `ignore cursor events`，避免拦截桌面点击。
- 拖动使用逻辑像素，系统边界与窗口定位使用物理像素，并通过显示器缩放因子转换。
- 吸附后的正常位置保存到 Tauri Store；半隐藏只改变临时窗口位置，不覆盖持久位置。

## 平台适配

- 公共接口隐藏平台差异。
- Windows 专属代码使用 `cfg(target_os = "windows")` 隔离。
- macOS 开发版本可以对暂不支持的能力返回明确的 `unsupported_platform` 错误，不静默失败。
