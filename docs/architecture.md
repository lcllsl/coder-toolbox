# 架构说明

## 窗口

- `orb-window`：悬浮球、第一层五个分类花瓣和提醒轻卡片。
- `panel-window`：五类功能面板、设置和二级弹窗；默认隐藏。“加密凭据夹”位于“快捷入口”的第四个顶层子页，不增加第六个花瓣或新的系统窗口。
- 两个窗口加载同一个前端入口，根据 Tauri 窗口标签挂载不同根组件。

## 边界

- Vue 负责 UI、状态、动画、转换逻辑和输入校验。
- `src/services/tauri` 是所有前端系统调用的唯一入口。
- Rust command 负责窗口、文件、剪贴板、托盘、快捷键和受控进程启动等系统能力。凭据派生、认证加密、会话密钥和敏感剪贴板是安全边界例外，也必须留在 Rust 侧。
- 设置与 SQLite 将分别通过 repository 封装，组件不会直接访问存储插件。
- `useVaultStore` 只维护解锁后的内存视图和交互状态，通过 `src/services/tauri/vault.ts` 调用 Rust；组件不接触密钥、SQL 或密码学实现。

## 窗口通信

- 需要返回值的操作使用 Tauri command，例如打开、关闭或切换窗口。
- 小型状态通知使用定向事件，例如面板分类变化。
- 剪贴板图片等大数据不通过事件传递，使用文件或 command/channel。

## 数据与设置

- 主题、运行模式、快捷键、悬浮球外观、提醒配置、收藏和常用入口通过 repository 封装后写入 Tauri Store。
- 凭据夹自动锁定时长也是非敏感设置，只允许 1、5、15、30 分钟，默认 5 分钟。
- 提醒记录、剪贴板历史、临时中转元数据与最近使用通过 repository 访问 SQLite。
- `vault_metadata` 保存版本、salt、KDF 参数和加密验证值；`vault_items` 只保存 ID、ciphertext、nonce 和时间。系统名称、用户名、密码、备注整体加密后写入，不存在对应明文列。
- 仅凭据夹 payload 使用应用层加密。普通业务 SQLite 表、剪贴板历史和文件缓存继续沿用既有格式，不因此改成整库加密。
- 主密码、派生密钥、解密后的凭据列表、最后活动时间和临时显示状态不得持久化；派生密钥仅存在 Rust 进程内存，解密列表仅存在前端内存。
- 剪贴板图片缓存和临时中转副本只写入应用私有目录；清理命令不会接收任意用户目录作为删除目标。
- 普通数据清理默认不包含凭据夹；只有用户主动选中凭据夹并通过额外一次永久删除确认后，才以同一事务删除 items 和 metadata。
- “清除数据并重置设置”先清除普通业务数据，再恢复默认快捷键、工作模式和各模块设置，并关闭开机启动；不得隐式删除凭据夹。

## 凭据夹安全边界

- 主密码使用 Argon2id v19 派生 32 字节密钥，当前参数为 64 MiB 内存、3 次迭代、1 路并行和 16 字节安全随机 salt。
- 每条凭据使用 XChaCha20-Poly1305 整体认证加密，nonce 为 24 字节安全随机值，凭据 ID 作为 associated data。
- 会话密钥由 Rust `VaultState` 管理；手动锁定、功能面板关闭、应用退出或 1/5/15/30 分钟无活动超时都会释放会话。Rust generation 阻止锁定期间的在途解锁重建会话，mutation gate 串行化初始化、认证、CRUD 和重置；前端串行化认证请求，以 epoch 和 latest-wins 状态协调丢弃锁定后才返回的明文或陈旧状态结果。每次锁信号都清空解密列表、搜索、主密码表单与显示状态。
- 搜索在前端解锁态内存中按系统名称和用户名执行。查看密码是显式操作，10 秒后自动恢复掩码。
- 当前没有接入系统锁屏或 suspend/resume 立即锁定，也不提供主密码找回或修改；忘记密码只能经双重确认永久删除并重新初始化。

## 敏感剪贴板路径

- 用户名和密码复制复用现有剪贴板系统，但统一经受控 Rust 接口写入；进程内只保留写入代次、系统剪贴板序列号和 SHA-256 摘要，不保留用于协调的额外明文副本。marker 不按短墙钟超时或固定队列容量淘汰，以保护被系统暂停后才恢复的监听请求。
- 监听器用序列号与摘要识别自身敏感写入，因此凭据不会进入“冒泡”自身历史。
- 密码默认 15 秒、用户名默认 30 秒后尝试清空。只有代次仍为最新、系统序列号未变且当前内容摘要仍匹配时才清理；瞬时剪贴板占用/读写失败会有限重试，期间用户复制的新内容不会被误删。
- Windows 适配层写入 `ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory` 和 `CanUploadToCloudClipboard` 三个格式，实际系统历史与云剪贴板行为仍需 Windows 11 实机验证。
- macOS 没有当前实现可用的等价系统历史排除能力，明确返回不支持；应用自身历史忽略和条件自动清理仍然执行。

## 系统设置与模式

- `app/stores/settings.ts` 是工作、静默、完全暂停三种模式的前端事实来源。
- 健康提醒卡由悬浮球窗口维护唯一的当前提醒与 60 秒计时器；周期健康检查不得重置已有卡片计时。超时复用正常完成事务，记录 `completed`、移出待处理队列并重新排期。倒计时环仅负责视觉反馈，不作为业务计时事实来源。
- `orb-window` 将模式映射到健康提醒和剪贴板监听；托盘通过定向事件请求切换，再由设置 store 持久化。
- 全局快捷键采用“先注册新组合、成功后释放旧组合”，避免设置失败时丢失原快捷键。
- 开机启动、全局快捷键、托盘勾选和退出均通过 `src/services/tauri/settings.ts` 进入受控插件或 Rust command。

## 悬浮球窗口

- 前端 Pinia store 维护单一 `OrbUiState` 状态机，非法跨级转换会被拒绝。
- Rust 根据悬浮球所在显示器的物理工作区计算展开窗口、面板位置和四边吸附目标。
- 花瓣位置由 TypeScript 纯函数计算，便于覆盖左右、上下和角落边界测试。
- 展开窗口通过全局光标位置轮询判断是否位于主球/花瓣热区；透明区域临时启用 `ignore cursor events`，避免拦截桌面点击。
- 拖动使用逻辑像素，系统边界与窗口定位使用物理像素，并通过显示器缩放因子转换。
- 吸附后的正常位置保存到 Tauri Store；半隐藏只改变临时窗口位置，不覆盖持久位置。

## 平台适配

- 公共接口隐藏平台差异。
- Windows 专属代码使用 `cfg(target_os = "windows")` 隔离。
- macOS 开发版本可以对暂不支持的能力返回明确的 `unsupported_platform` 错误，不静默失败。
- 加密凭据夹的 Windows 11 原生剪贴板格式、安装包和完整 E2E 尚未验证；文档与 UI 不把跨平台代码实现表述为实机通过。
